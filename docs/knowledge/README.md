# 踏んだこと・決めた理由

**同じ罠に2度目で刺されないための記録。** 実装で踏んだ症状、なぜその形にしたか、実測値を置く。

- **基本設計・ファイル構成・コマンドはここには無い** —— [`../`](../) の各文書が正
- **秒数・CPU 使用率・件数は仕様ではない。** マシンとネットワークで変わる。ここに残してあるのは
  「そのとき何が起きたか」の記録で、次に同じ数字が出ることの保証ではない

## 書き方

放っておくと測定そのものが積もるので、次を守る。

- **実測は結論と測定条件だけ残す。生ログは残さない。** 「何を測って何が分かったか」と「どの環境で
  測ったか」があれば足りる。`top` の推移・`Player.log` の抜粋・1件ずつの所要時間は、次に測り直すとき
  **同じ条件で取り直す**ものなので、貼っておく価値が無い
- **全項目パスした実機確認は1行にする。** 「いつ・何を・全部通った」で足りる。
  **残すのは「ここが直っていなかった」「前の記述を訂正した」を含む行だけ**
- **同じ測定を世代をまたいで取り直したら、古い回は基準値の1行に縮める**
- **同じ注意書きを繰り返さない。** リポジトリ全体に効くルール（上の「秒数は仕様ではない」など）は
  この README が1回言えば足りる
- **「仕組みで消えた罠」は消さない。** その仕組みを将来外すと再発するので、1〜2行に縮めて残す
